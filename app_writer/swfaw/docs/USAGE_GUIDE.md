# Spring WebFlux Application Writer v2 - Usage Guide

## Installation

1. Install Python dependencies:
```bash
cd emotisense-ai/swfaw_v2
pip install -r requirements.txt
```

## Complete Workflow: SQL to Running Application

### Step 1: Convert SQL Schema to JSON

Convert your SQL schema file to an application definition JSON:

```bash
cd emotisense-ai/swfaw_v2
python convert_sql.py ../mysql_database_design/your_schema.sql
```

This creates `application_definition.json` in the same directory as your SQL file.

You can also specify a custom output location:
```bash
python convert_sql.py ../mysql_database_design/your_schema.sql --output ../generated_application/my_app/application_definition.json
```

### Step 2: Generate Spring WebFlux Application

Generate the application using the JSON definition:

```bash
python main.py --input ../mysql_database_design/application_definition.json --output ../generated_application/my_app
```

The generator will:
- Read the application definition
- Generate all Java code (entities, DTOs, repositories, services, controllers)
- Create configuration files
- Save a copy of `application_definition.json` in the generated app folder

### Step 3: Setup Database

Run the authentication and activity tracking schemas:

```bash
# Create the database
mysql -u root -p -e "CREATE DATABASE your_database_name;"

# Run your original SQL schema
mysql -u root -p your_database_name < ../mysql_database_design/your_schema.sql

# Run authentication schema
mysql -u root -p your_database_name < ../generated_application/my_app/auth-schema.sql

# Run activity tracking schema
mysql -u root -p your_database_name < ../generated_application/my_app/activity-tracking-schema.sql
```

### Step 4: Build and Run

```bash
cd ../generated_application/my_app
mvn clean install
mvn spring-boot:run
```

### Step 5: Complete Setup

1. Navigate to: http://localhost:8081/setup (or your configured port)
2. Create the initial admin user
3. Access Swagger UI: http://localhost:8081/swagger-ui.html

## File Locations

### swfaw_v2 Directory (Generator Code Only)
- `main.py` - Application generator
- `convert_sql.py` - SQL to JSON converter
- `models/` - Data models
- `transformers/` - Transformation logic
- `generators/` - Code generators
- `templates/` - Jinja2 templates
- Documentation files

**No application-specific files should be in this directory!**

### Application Directories
Each generated application lives in its own folder:
```
emotisense-ai/generated_application/my_app/
├── application_definition.json    ← Application definition
├── auth-schema.sql                ← Authentication tables
├── activity-tracking-schema.sql   ← Activity tracking tables
├── test-data.json                 ← Sample test data
├── pom.xml                        ← Maven configuration
├── README.md                      ← Application-specific docs
└── src/                           ← Generated Java code
```

### SQL Schema Files
Store your SQL schemas in:
```
emotisense-ai/mysql_database_design/
├── your_schema.sql
└── application_definition.json    ← Generated by convert_sql.py
```

## Database Definition Format

```json
{
  "projectMetadata": {
    "name": "my-application",
    "groupId": "com.example",
    "artifactId": "my-app",
    "version": "1.0.0",
    "port": 8080,
    "database": {
      "type": "mysql",
      "host": "localhost",
      "port": 3306,
      "name": "my_database"
    }
  },
  "tables": [
    {
      "name": "ems_course",
      "columns": [
        {
          "name": "course_id",
          "type": "BIGINT",
          "primaryKey": true,
          "nullable": false
        },
        {
          "name": "course_name",
          "type": "VARCHAR(255)",
          "nullable": false
        }
      ],
      "relationships": []
    }
  ]
}
```

## Supported SQL Types

- BIGINT → Long
- INT, INTEGER → Integer
- SMALLINT → Short
- VARCHAR, CHAR, TEXT → String
- BOOLEAN, BOOL → Boolean
- DATE → LocalDate
- DATETIME, TIMESTAMP → LocalDateTime
- DECIMAL, NUMERIC → BigDecimal
- FLOAT → Float
- DOUBLE → Double

## Root Entities

Root entities are automatically detected based on naming:
- course
- institution
- jobpost
- community
- user

Root entities automatically get:
- `is_public` field
- Authorization checks in service layer
- ADMIN access granted on creation

## Features

### Automatic Features
- ✅ Soft delete (deletedAt field)
- ✅ Audit fields (createdAt, updatedAt)
- ✅ JWT authentication
- ✅ Entity-level authorization
- ✅ Reactive programming (Mono/Flux)
- ✅ REST APIs
- ✅ Swagger documentation
- ✅ Input validation
- ✅ Error handling

### Generated Endpoints

For each entity (e.g., Course):
- POST /api/courses - Create
- GET /api/courses/{id} - Find by ID
- GET /api/courses - Find all
- PUT /api/courses/{id} - Update
- DELETE /api/courses/{id} - Soft delete

## Troubleshooting

### Issue: Generated code doesn't compile
- Check that all required dependencies are in pom.xml
- Ensure Java 17+ is installed
- Run `mvn clean install` to download dependencies

### Issue: Database connection fails
- Update database credentials in application.yml
- Ensure database server is running
- Check database name and port

### Issue: Authorization not working
- Implement the authorization service logic
- Check JWT token is included in requests
- Verify user has required access level
