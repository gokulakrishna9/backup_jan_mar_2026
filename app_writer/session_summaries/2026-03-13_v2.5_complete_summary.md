## Overview

Removed dynamic SQL generation from authorization layer and updated to use new schema design with pre-generated custom queries.

## What Changed

### 🔴 Removed (Security Risk)
- `QueryDefinition` model - Dynamic query definition
- `QueryExecutor` class - Runtime SQL string builder

### ✅ Added (Secure)
- `AccessControlConstants` - 8 access operation constants
- `CustomQueryRegistry` - Registry for pre-generated query executors
- 5 new scope entities with repositories:
  - `DocumentGroupTableScope` / Repository
  - `DocumentGroupTableRecordScope` / Repository
  - `DocumentGroupQueryScope` / Repository
  - `DocumentGroupQueryRecordScope` / Repository
  - `DocumentGroupMembership` / Repository

### 🔄 Updated
- `DocumentGroupMatcher` - Uses new scope tables, supports 9 document group types
- `PermissionResolver` - Uses new membership model
- `AuthorizationService` - Simplified with new schema
- All generator methods updated
- `main.py` - Generates new components

### ⚠️ Deprecated (Backward Compatible)

- `DocumentPermission` entity/repository

## New Schema Support

### 9 Document Group Types:
1. CREATOR_RECORDS - User's own records
2. SINGLE_RECORD - One specific record
3. MULTIPLE_RECORDS - Multiple specific records
4. TABLE_USER - Entire table (user-level)
5. TABLE_ADMIN - Entire table (admin-level)
6. TABLE_MULTIPLE_USER - Multiple tables (user-level)
7. TABLE_MULTIPLE_ADMIN - Multiple tables (admin-level)
8. QUERY_SPECIFIC - Query with specific records (READ-only)
9. QUERY_ALL - All query results (READ-only)

### 8 Access Control Operations:
1. READ
2. CREATE
3. UPDATE
4. DELETE
5. GRANT_ACCESS
6. EXPORT
7. SHARE
8. AUDIT

### Scope Tables:
- `document_group_table_scope` - Table-level permissions with 8 ACL flags
- `document_group_table_record_scope` - Record-level permissions with 8 ACL flags
- `document_group_query_scope` - Query-based permissions (references query_layer.json)
- `document_group_query_record_scope` - Specific records for queries
- `document_group_membership` - User/group membership in document groups

## Security Improvements

### Before (v2.4.0):
```java
// Dynamic SQL building at runtime
String sql = "SELECT COUNT(*) FROM " + tableName + " WHERE id = " + recordId;
if (conditions != null) {
    sql += " AND " + buildConditions(conditions); // String concatenation
}
```

### After (v2.5.0):
```java
// Pre-generated type-safe queries
customQueryRegistry.executeQuery("findActiveUsers", tableName, recordId);
// Delegates to: userCustomQueryRepository.checkActiveUser(recordId)
```

## Benefits

✅ **Security:** No dynamic SQL generation, no injection risk  
✅ **Performance:** No runtime query building overhead  
✅ **Maintainability:** Queries defined in JSON, version controlled  
✅ **Type Safety:** All queries validated at generation time  
✅ **Flexibility:** Still supports complex authorization rules  
✅ **Backward Compatible:** Old components marked deprecated but functional
